1. CONTROLLER ANALYSIS (OceanImportController.php)
--------------------------------------------------

Lines: 2,434
Methods: 57 public/protected
Complexity: HIGH

✓ GOOD PRACTICES:
- Uses Service Layer pattern (OceanImportService)
- Proper authorization with Policy
- Database transaction in Service
- Error handling with try-catch
- Validation via Form Requests
- Proper relationship eager loading

✗ PROBLEMS IDENTIFIED:

a) METHOD BLOAT - Too many responsibilities
   - 57 methods in one controller (SHOULD BE MAX 15-20)
   - Many methods doing similar things (duplication)
   
b) DUPLICATE FILTER LOGIC
   Location: applyFiltersToQuery() method (lines 77-141)
   Problem: Same filter logic repeated in:
     - index() 
     - mblList()
     - hblList()
     - containerList()
   
   Current: 4 copies of similar code (~200 lines wasted)
   Should be: 1 trait or helper method (~50 lines)
   
c) COPY OPERATION COMPLEXITY
   Location: create() method when ?copy parameter exists (lines 170-280)
   Problem: 110 lines of nested loops and complex logic
   Issue: Difficult to test, maintain, debug
   Solution: Extract to CopyShipmentService class
   
d) AJAX RESPONSE DUPLICATION
   Pattern repeated 5+ times:
   ```php
   if ($request->ajax() || $request->wantsJson()) {
       try {
           $html = view(...)->render();
           $pagination = view(...)->render();
           return response()->json([...]);
       } catch (\Exception $e) {
           return response()->json([...], 500);
       }
   }
   ```
   Solution: Create AjaxPaginationResponse helper
   
e) CHARGE MAPPING LOGIC
   Location: OceanImportService (lines 75-110, 180-230)
   Problem: Identical charge mapping code in store() and update()
   Duplication: 100+ lines duplicated
   Solution: Extract to mapChargeData() private method

   All routes should be in a group:

   ```php
       ->group(function() { ... });
   ```
